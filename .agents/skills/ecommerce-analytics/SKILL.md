# 电商经营分析

当用户要分析电商订单、检查数据质量或经营指标、查看 RFM 分层，或生成 Excel/HTML 报告时，使用本仓库已有的分析流水线。

## 执行步骤

1. 确认当前工作区是本仓库（根目录包含 `pyproject.toml` 和 `src/ecommerce_analytics/cli.py`），并确认用户提供的输入文件可从当前运行环境读取。
2. 保留原始输入。只把用户明确指定的订单文件作为真实数据；`data/` 和 `data/portfolio_demo/` 下的示例是模拟数据，结论必须标明为演示结果。
3. 在 `artifacts/ai-analysis/` 下选一个唯一的新输出目录，例如 `orders-YYYYMMDD-HHMMSS`，先检查目录不存在，避免覆盖之前的报告。
4. 使用仓库内的启动脚本调用项目 CLI，确保执行的是当前工作区代码，不重写或绕过分析模块：

   ```text
   python scripts/run_analysis.py run --input "<订单文件路径>" --output "artifacts/ai-analysis/<唯一目录名>"
   ```

   脚本或依赖不可用时，先检查当前 Python 环境及安装说明；不要擅自安装到系统 Python，也不要修改输入文件。
5. 仅在命令成功后读取输出目录中的 `analysis.json`、`cleaning_log.json` 和校验文件。详细订单模式通常生成 `validation.md`，订单级平台导出模式生成 `validation.json`；按实际存在的文件核验，不假设两种模式产物完全相同。若校验失败，明确指出失败项，不把未通过结果描述为成功。
6. 用中文总结核心指标、数据质量问题、可用分析维度、指标口径和局限，给出报告文件路径。只摘录回答所需的汇总，不复述客户或订单明细中的个人信息。

## 口径约束

- 缺少字段时说明相应分析不可用，不补造商品、用户、流量或履约数据。
- 转化指标只来自明确提供的流量表，不能从订单表反推曝光、访客或加购。
- 不推断利润、毛利率、ROI 或因果效果；数据不足时直接说明。
- 按输出中的分母和口径解释退款率、迟发率、逾期率等比例，不混用分母。
- 报告应包含清洗决策、验证结果和数据局限；区分样本分析与真实业务结论。
